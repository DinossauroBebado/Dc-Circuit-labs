Objetivo do Projeto

A Metabee Wifi Connect V1.0 transforma o protótipo atual em uma placa de circuito impresso dedicada ("Bare ESP32"). O objetivo é reduzir o tempo de montagem, facilitar a adequação aos padrões da Anatel e preparar o produto para produção em escala.

  • Microcontrolador: módulo ESP32-WROOM-32D (4 MB de flash) com antena de PCB na borda da placa
  • Display: módulo TFT 1.8" ST7735 (128×160, SPI) soldado por barra de pinos
  • Armazenamento: slot microSD do próprio módulo do display, usado para guardar endereços MAC
  • Interface: botão lateral (SW1) posicionado para evitar toques acidentais, mais o conector SWT para botão externo
  • Mecânica: 4 furos de 3,2 mm (M3), alinhados com os furos do módulo do display, para fixação na carcaça plástica impressa em 3D

Alimentação e Barramentos

Principais caminhos de energia e de comunicação da placa:

  • Entrada 5 V: USB-C 1 (borda inferior), USB-C 2 (lateral) ou conector PWR. Os conectores USB-C servem só para alimentação.
  • Regulação: AMS1117-3.3 (U1) gera 3,3 V a partir de 5 V para o ESP32, o display e o cartão SD
  • SPI (VSPI): SCK GPIO18, MOSI GPIO23 e MISO GPIO19, compartilhados entre o display (CS GPIO5) e o microSD (CS GPIO14)
  • UART0: GPIO1 (TX) e GPIO3 (RX) no conector H1, para gravação e monitor serial
  • Gravação fechada: o conector H1 fica dentro do produto e não é acessível ao usuário final

Critérios de Aceitação do Projeto

Requisitos mensuráveis definidos no escopo técnico para aprovação do hardware:

  • Operação contínua: no mínimo 20 horas sem falhas críticas, sem superaquecimento e sem reinicializações por instabilidade de tensão.
  • Estabilidade operacional: nenhuma falha ou glitch visual na tela, nenhuma queda do Wi-Fi e nenhum erro de gravação ou leitura no cartão SD.
  • Condições de operação: funcionamento garantido nas condições ambientais especificadas, com a proteção da entrada USB-C operando conforme o projeto.

1. DISPLAY TFT + BOTÃO + LED DE STATUS — Firmware de Teste
Alterna entre duas imagens gravadas na flash a cada toque no botão (GPIO 27) e acende o LED de status (GPIO 2) enquanto o botão está pressionado.

Resumo da Validação

O firmware inicializa o display ST7735 pelo barramento VSPI e desenha uma imagem RGB565 de 128×160 guardada na flash do ESP32, sem depender do cartão SD. Cada toque no botão lateral (ou no botão externo ligado ao SWT) troca a imagem, com debounce de 200 ms. O LED de status acompanha o estado do botão. O monitor serial roda a 115200 baud.

src/main.cpp 
/*
 * Firmware ESP32-WROOM + display TFT ST7735 1.8" (SPI)
 *
 * Ao pressionar o botão no GPIO 27, alterna entre duas imagens embutidas
 * na flash do ESP32 (não depende de cartão SD).
 *
 * Pinagem do display:
 *   VCC   -> 3.3V   (NUNCA 5V)
 *   GND   -> GND
 *   CS    -> GPIO 5
 *   RESET -> GPIO 4
 *   A0/DC -> GPIO 16
 *   SDA/MOSI -> GPIO 23
 *   SCK   -> GPIO 18
 *   LED   -> GPIO 17
 *
 *   Botão -> GPIO 27 (outro terminal no GND, usa INPUT_PULLUP)
 *   LED indicador (onboard do ESP32) -> GPIO 2, acende enquanto o
 *   botão estiver pressionado
 *
 * As imagens (src/img1.h e src/img2.h) são geradas a partir dos arquivos
 * do projeto pelo script generate_headers.py (Pillow), já redimensionadas
 * para 128x160 e convertidas para RGB565.
 */

#include <Arduino.h>
#include <Adafruit_GFX.h>
#include <Adafruit_ST7735.h>
#include <SPI.h>

#include "img1.h"
#include "img2.h"

// ---------- Pinos do display ----------
#define TFT_CS    5
#define TFT_RST   4
#define TFT_DC    16
// MOSI (23) e SCK (18) usam o barramento VSPI padrão do ESP32

// ---------- Pino do backlight ----------
#define TFT_LED   17

// ---------- Botão ----------
#define BUTTON_PIN  27
#define DEBOUNCE_MS 200

// ---------- LED indicador (onboard do ESP32) ----------
#define STATUS_LED_PIN 2

Adafruit_ST7735 tft = Adafruit_ST7735(TFT_CS, TFT_DC, TFT_RST);

struct Image {
  const uint16_t* data;
  int16_t width;
  int16_t height;
};

const Image IMAGES[] = {
  { IMG1_DATA, IMG1_WIDTH, IMG1_HEIGHT },
  { IMG2_DATA, IMG2_WIDTH, IMG2_HEIGHT },
};
const uint8_t NUM_IMAGES = sizeof(IMAGES) / sizeof(IMAGES[0]);

uint8_t currentImage = 0;
unsigned long lastPressTime = 0;

void showImage(uint8_t index) {
  const Image &img = IMAGES[index];
  tft.drawRGBBitmap(0, 0, img.data, img.width, img.height);
}

void setup() {
  Serial.begin(115200);

  pinMode(BUTTON_PIN, INPUT_PULLUP);

  pinMode(STATUS_LED_PIN, OUTPUT);
  digitalWrite(STATUS_LED_PIN, LOW);

  pinMode(TFT_LED, OUTPUT);
  digitalWrite(TFT_LED, HIGH); // liga o backlight

  // Inicializa o display (chip ST7735, variante comum de módulos 1.8" 128x160)
  tft.initR(INITR_BLACKTAB);
  tft.setRotation(0);
  tft.fillScreen(ST77XX_BLACK);

  showImage(currentImage);
}

void loop() {
  // Botão ativo em nível baixo (INPUT_PULLUP)
  bool pressed = (digitalRead(BUTTON_PIN) == LOW);

  // LED acende enquanto o botão estiver pressionado
  digitalWrite(STATUS_LED_PIN, pressed ? HIGH : LOW);

  if (pressed) {
    unsigned long now = millis();
    if (now - lastPressTime > DEBOUNCE_MS) {
      lastPressTime = now;
      currentImage = (currentImage + 1) % NUM_IMAGES;
      showImage(currentImage);
    }
  }
}

2. GERAÇÃO DAS IMAGENS — Conversão PNG → RGB565 (generate_headers.py)
Script Python (Pillow) que converte as imagens do projeto em arrays C para gravar na flash do ESP32.

Como Funciona

Cada imagem é redimensionada para caber em 128×160 sem distorção, centralizada em fundo preto (letterbox) e convertida para RGB565 (16 bits por pixel). O resultado é gravado em src/img1.h e src/img2.h como arrays const uint16_t … PROGMEM, com 20.480 pixels (40.960 bytes) cada. Rode o script sempre que trocar as imagens, antes de compilar.

generate_headers.py 
#!/usr/bin/env python3
"""Converte as imagens do projeto em arrays C (RGB565) para embutir na flash do ESP32."""
from PIL import Image
import os

SRC_DIR = "/home/dino/DC_labs_proj/clistenes/firmware_teste_dc"
OUT_DIR = os.path.join(SRC_DIR, "src")

W, H = 128, 160

FILES = [
    ("2.png", "img1.h", "IMG1"),
    ("dccircuit_labs.png", "img2.h", "IMG2"),
]

def to_rgb565(r, g, b):
    return ((r & 0xF8) << 8) | ((g & 0xFC) << 3) | (b >> 3)

for src_name, header_name, macro_prefix in FILES:
    src_path = os.path.join(SRC_DIR, src_name)
    im = Image.open(src_path).convert("RGB")

    src_ratio = im.width / im.height
    dst_ratio = W / H
    if src_ratio > dst_ratio:
        new_w = W
        new_h = round(W / src_ratio)
    else:
        new_h = H
        new_w = round(H * src_ratio)

    im_resized = im.resize((new_w, new_h), Image.LANCZOS)
    canvas = Image.new("RGB", (W, H), (0, 0, 0))
    off_x = (W - new_w) // 2
    off_y = (H - new_h) // 2
    canvas.paste(im_resized, (off_x, off_y))

    pixels = list(canvas.getdata())
    values = [to_rgb565(r, g, b) for (r, g, b) in pixels]

    out_path = os.path.join(OUT_DIR, header_name)
    with open(out_path, "w") as f:
        f.write(f"// Gerado automaticamente a partir de {src_name} ({W}x{H}, RGB565)\n")
        f.write("#pragma once\n")
        f.write("#include <Arduino.h>\n\n")
        f.write(f"#define {macro_prefix}_WIDTH  {W}\n")
        f.write(f"#define {macro_prefix}_HEIGHT {H}\n\n")
        f.write(f"const uint16_t {macro_prefix}_DATA[{macro_prefix}_WIDTH * {macro_prefix}_HEIGHT] PROGMEM = {{\n")
        line = "  "
        for i, v in enumerate(values):
            line += f"0x{v:04X},"
            if (i + 1) % 16 == 0:
                f.write(line + "\n")
                line = "  "
        if line.strip():
            f.write(line + "\n")
        f.write("};\n")

    print(f"{src_name} -> src/{header_name} ({len(values)} pixels, {len(values)*2} bytes)")

Como Programar

Gravação do firmware pelo conector H1 com um conversor USB-TTL e dois botões (BOOT e RESET). Os conectores USB-C só alimentam a placa: não têm linhas de dados.

Material Necessário

  • Conversor USB-TTL de 3,3 V (CH340, CP2102 ou FT232). Se tiver jumper de tensão, coloque em 3V3.
  • 2 botões táteis (push-button normalmente aberto): um para BOOT e outro para RESET.
  • Jumpers Dupont e uma protoboard pequena para o GND comum.
  • Nenhuma fonte extra: o pino 5V do conversor alimenta a placa pelo conector PWR, e basta um cabo USB. Se preferir, use a USB-C da placa no lugar do fio de 5 V.
  • Computador com VS Code + PlatformIO (ou Arduino IDE com o pacote ESP32).

Por que dois botões?

O ESP32 escolhe o modo de inicialização no momento em que sai do reset:

  • BOOT (GPIO0) em nível baixo ao sair do reset: entra no modo de gravação e espera o firmware pela UART.
  • BOOT solto (nível alto): executa o firmware gravado na flash.
  • A placa já tem pull-up de 10 kΩ no BOOT (R4) e no RESET (R3). Cada botão só precisa ligar o pino ao GND.
  • As linhas DTR/RTS do conversor não vão para a placa, então a entrada no modo de gravação é feita à mão pelos botões.

Esquema de Ligação no Conector H1

Zoom no conector de gravação (lado dos componentes), com o conversor USB-TTL, os dois botões e o fio de 5 V no conector PWR. Clique na imagem para ampliar.

Pino Sinal Ligar em Observação
1 GND GND do conversor + uma perna de cada botão Referência comum, obrigatória
2 RX_ESP · GPIO 3 TXD do conversor Ligação cruzada: TX do conversor → RX da placa
3 TX_ESP · GPIO 1 RXD do conversor Ligação cruzada: TX da placa → RX do conversor
4 RESET · EN Botão RESET (outra perna no GND) Pressionado, o ESP32 fica em reset

6 3V3 Não conectar Vai direto no ESP32, sem regulador: nunca ligue 5 V aqui

O 5V do conversor vai no PWR +, que passa pelo regulador. Nunca ligue 5 V no pino 6 (3V3) do H1: esse pino vai direto no ESP32 e o módulo queima. Com o fio de 5 V ligado, deixe a USB-C desconectada, porque as duas estão na mesma trilha de 5 V, sem diodo. Mantenha o conversor com nível lógico de 3,3 V (jumper em 3V3): um sinal de 5 V no RX pode danificar o ESP32.

Colocando a Placa em Modo de Gravação

1

Faça as ligações da tabela acima e conecte o conversor ao computador. A placa é alimentada pelo 5V do conversor, e os LEDs 5V e 3V3 acendem.

2

Pressione e segure o botão BOOT.

3

Com o BOOT ainda pressionado, aperte e solte o botão RESET.

4

Solte o botão BOOT. O ESP32 agora espera o firmware; no monitor serial (115200 baud) aparece waiting for download.

5

Inicie a gravação no computador (PlatformIO ou Arduino IDE, abaixo).

6

Ao final (Hard resetting via RTS pin...), aperte RESET uma vez para rodar o firmware novo. A placa não reinicia sozinha porque o RTS não está ligado.

Alternativa: Arduino IDE

  • Placa: ESP32 Dev Module (pacote "esp32" da Espressif no Gerenciador de Placas)
  • Porta: a do conversor USB-TTL
  • Upload Speed: 460800 (ou 115200 se houver erros)
  • Coloque a placa em modo de gravação (BOOT + RESET) e clique em Carregar.
  • Quando aparecer Hard resetting via RTS pin..., aperte RESET.

Conferência Antes de Gravar

  • Conversor em 3,3 V
  • TX → RX e RX → TX (ligação cruzada)
  • GND do conversor ligado ao pino 1 do H1
  • Pino 6 (3V3) do H1 desconectado
  • 5V do conversor no PWR + e USB-C desconectada (LEDs 5V e 3V3 acesos)
  • Monitor serial fechado antes de iniciar a gravação

Problemas Comuns

Mensagem / Sintoma Causa Provável Solução
Failed to connect to ESP32: No serial data received. TX/RX invertidos, GND não ligado ou placa sem alimentação Confira a ligação cruzada TX → RX, o GND no pino 1 e os LEDs de alimentação
Wrong boot mode detected (0x13)! The chip needs to be in download mode. A placa não entrou em modo de gravação Refaça a sequência BOOT + RESET e confira o fio do botão BOOT no pino 5
Permission denied: '/dev/ttyUSB0' Usuário sem acesso à porta serial (Linux) sudo usermod -aG dialout $USER, depois saia e entre na sessão
