📋 Visão Geral do Sistema

O sistema Rogge V4.1 foi projetado para controle de precisão e prototipagem ágil com integração IoT e suporte a iBOM 3D interativo.

  • MCU Principal: ESP32-S3 (Dual-Core Xtensa LX7)
  • Co-processador: Sem C6 Auxiliar (Removido nesta revisão de hardware)
  • Comunicação: RS-485 Industrial, SPI, I2C, UART
  • Alimentação: 24V DC Nominal (máx. 36V DC Pico) com proteção contra inversão
  • Revisão de Hardware: V4.1 (DC Circuit Labs)

⚙️ Especificações de Montagem

Instruções para teste, montagem SMT/THT e inspeção visual da placa Rogge V4.1:

  • Processo SMT: Montagem de precisão com pastas de solda SAC305 e inspeção AOI.
  • Modificação USB: Capacitores de 470µF substituídos por 47µF para baixar a capacitância nas trilhas USB.
  • Inspeção THT: Verificação dos conectores e componentes no painel iBOM abaixo.
  • Testes Funcionais: Validação de hardware realizada (sem testes de Wi-Fi e 1-Wire por ausência de antena/sensor).

⚠️ Sessão de Observações e Modificações de Campo

Relatório técnico detalhando modificações de hardware, comportamentos de inicialização e ensaios pendentes na placa Rogge V4.1.

🔌 Instabilidade no USB para Programação

Comportamento Observado: Foram identificadas instabilidades e interrupções na comunicação USB durante o processo de gravação do microcontrolador via CH340C.

Modificação de Hardware Efetuada:
SUBSTITUÍDOS CAPACITORES DE 470µF POR 47µF — Redução da capacitância total nas trilhas da interface USB para evitar acoplamento excessivo e manter a integridade do sinal serial durante o upload.

⚡ Comportamento dos Relés no Start-up

Comportamento Observado: Às vezes os relés são acionados momentaneamente no exato instante em que a placa é ligada (energização inicial).

Ação Tomada & Ponto de Atenção:
Reduzimos ao máximo a duração desse pulso residual através de otimizações na inicialização dos GPIOs no firmware e circuito de latch. No entanto, o tempo não foi totalmente zerado.

🔍 Recomendação: Verificar se este tempo residual de comutação dos relés durante o boot pode ser um problema para as cargas e equipamentos conectados na aplicação final.

🌡️ Testes no Barramento 1-Wire

Status de Validação: Não realizados.

Não foram realizados testes funcionais com o protocolo 1-Wire nesta bancada devido à falta do sensor de temperatura/pressão físico (ex: DS18B20) para conexão e amostragem.

📶 Testes de Comunicação Wi-Fi

Status de Validação: Não realizados.

Não foram executados testes de transmissão e recepção de dados via Wi-Fi devido à ausência da antena de RF física conectada ao pino U.FL da placa durante os procedimentos de ensaio.

Teste #2 — Tensão de Entrada VIN (24V Nominal / máx 36V Pico)
ADC1 (GPIO 1) — Divisor de tensão resistivo + modo Alta Impedância (Hi-Z)
APROVADO
▼

1. Contexto de Hardware

  • Circuito: Divisor de Tensão Resistivo integrado na PCB, projetado para adequar a tensão nominal de 24V DC (pico máximo de até 36.0V DC) para 0.0V a 3.3V DC no pino do ESP32.
  • Interface: ADC1 do ESP32-S3 — Pino GPIO 1 (ADC1_CH0).
  • Bibliotecas: Arduino.h, driver/gpio.h (para desativação de pull-up/pull-down).

2. Configurações de Build

ini
[env:EX_TENSAO_VIN]
build_src_filter = -<*> +

3. O que foi feito

  • Configuração do ADC em 12 bits (0 a 4095) e atenuação de 11dB (0 a 3.3V no GPIO1).
  • Configuração do pino em Alta Impedância (Hi-Z) com gpio_pullup_dis() e gpio_pulldown_dis().

4. Código Fonte (main.cpp)

C++ — COMUNICACAO_IHM/main.cpp
#include <Arduino.h>

// RS485 (THVD1450DR)
#define PIN_RS485_R     41
#define PIN_RS485_RE_DE 40
#define PIN_RS485_D     42
#define RS485_BAUD_RATE 9600

// Relés (74HC595D + ULN2803)
#define PIN_CS2_LATCH 21
#define PIN_CLOCK     12
#define PIN_MOSI      11

uint8_t estadoReles = 0x00;
unsigned long ultimoEnvio = 0;
const unsigned long INTERVALO_ENVIO = 20000;
unsigned long numeroSequencial = 1;

void atualizarReles(uint8_t estado)
{
    digitalWrite(PIN_CS2_LATCH, LOW);
    shiftOut(PIN_MOSI, PIN_CLOCK, MSBFIRST, estado);
    digitalWrite(PIN_CS2_LATCH, HIGH);
}

void enviarNumeroRS485()
{
    digitalWrite(PIN_RS485_RE_DE, HIGH);
    delay(5);
    String pacote = "NUM:" + String(numeroSequencial) + "\n";
    Serial1.print(pacote);
    Serial1.flush();
    delay(5);
    digitalWrite(PIN_RS485_RE_DE, LOW);
    Serial.printf("[TX] Número enviado: %lu\n", numeroSequencial);
    numeroSequencial++;
}

void setup()
{
    Serial.begin(115200); delay(2000);
    Serial.println("=================================================");
    Serial.println(" DC Circuit Labs - Placa Rogue v4.1 (IHM Test)  ");
    Serial.println("=================================================");

    pinMode(PIN_CS2_LATCH, OUTPUT);
    pinMode(PIN_CLOCK, OUTPUT);
    pinMode(PIN_MOSI, OUTPUT);
    atualizarReles(estadoReles);

    pinMode(PIN_RS485_RE_DE, OUTPUT);
    digitalWrite(PIN_RS485_RE_DE, LOW);
    Serial1.begin(RS485_BAUD_RATE, SERIAL_8N1, PIN_RS485_R, PIN_RS485_D);

    enviarNumeroRS485();
    ultimoEnvio = millis();
}

void loop()
{
    if (millis() - ultimoEnvio >= INTERVALO_ENVIO)
    {
        ultimoEnvio = millis();
        enviarNumeroRS485();
    }

    if (Serial1.available())
    {
        String cmd = Serial1.readStringUntil('\n');
        cmd.trim();
        if (cmd.length() > 0)
        {
            Serial.printf("[RX] Comando: \"%s\"\n", cmd.c_str());
            if (cmd == "CMD:RELE1_TOGGLE" || cmd == "CMD:RELE1")
            {
                estadoReles ^= (1 << 0);
                atualizarReles(estadoReles);
                Serial.printf("  => Relé 1 %s! (0x%02X)\n",
                    (estadoReles & 0x01) ? "LIGADO" : "DESLIGADO", estadoReles);
            }
        }
    }
    delay(10);
}
